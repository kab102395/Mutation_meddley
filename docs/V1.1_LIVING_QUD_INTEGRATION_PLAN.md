# Mutation Meddley v1.1.0 — Living Qud Integration Plan

## Release thesis

`1.1.0` is the release where Mutation Meddley stops behaving only as a collection of deeply designed custom mutations and becomes a compatibility-oriented biological interpretation layer for the wider Caves of Qud ecosystem.

The release thesis is:

> **Recognize and react. Do not replace.**

The player-facing thesis is:

> **Everything has a biology. Even the things that do not.**

The goal is to make vanilla mutations, bodies, genotypes, subtypes, creature archetypes, terrain, liquids, technology, cybernetics, diseases, temporary transformations, and compatible third-party mod content meaningfully participate in Mutation Meddley ecology without Mutation Meddley taking ownership of those systems or rewriting their behavior.

The intended result is not that all of Qud becomes a Mutation Meddley object. The intended result is that Mutation Meddley can understand what Qud objects *mean* biologically, mechanically, environmentally, and behaviorally, then let Mutation Meddley-owned systems react to those meanings.

`1.1.0` should therefore be treated as an **integration-platform release**, not a large mutation-content release.

---

# 1. Prerequisite freeze

Implementation begins only from a `1.0.x` baseline that has passed the production-stabilization contract.

The following rules remain frozen unless a demonstrated runtime defect requires repair:

- rank 3 / 6 / 9 remain qualitative evolution milestones
- continuous rank progression remains derived from the owning mutation's live level
- existing save-state envelope and public persistent fields remain compatible
- normal gameplay remains fully usable without typing
- mutation-local ownership remains the default for gameplay effects
- dormant companion mutations remain ecologically inactive
- non-contact damage cannot spend close-contact resources
- synthetic bonus damage remains recursion-protected
- hidden-adaptation discovery remains behavior-based and save-persistent
- environmental predicates remain deterministic and documented
- no external mutation, item, body, race, faction, creature, or mod is silently rewritten simply because Mutation Meddley recognizes it

The core compatibility principle is:

> **External content supplies ecological context. Mutation Meddley-owned systems supply Mutation Meddley behavior.**

---

# 2. Primary goals

`1.1.0` has ten primary goals.

1. Build a universal semantic ecology vocabulary that can describe vanilla and modded content without relying primarily on hard-coded names.
2. Create read-only Ecology Profiles for actors, bodies, mutations, items, environments, and targets.
3. Define integration tiers so unknown or inferred content can participate safely without receiving uncontrolled high-power behavior.
4. Catalog and profile the full vanilla mutation roster.
5. Integrate genotype, subtype, body-plan, creature, liquid, environment, technology, cybernetic, disease, and transformation context where verified APIs support it.
6. Introduce a public, optional compatibility architecture so third-party mods can identify their content semantically without hard compile-time coupling.
7. Add deterministic provenance and conflict resolution for semantic traits.
8. Convert existing Mutation Meddley partner checks toward semantic queries where doing so improves compatibility without changing established gameplay contracts.
9. Build a developer Ecology Inspector capable of explaining exactly why an ecological relationship is active.
10. Keep the runtime cost bounded through explicit stable/dynamic caching boundaries and event-driven invalidation.

---

# 3. Explicit non-goals

The initial `1.1.0` pass does **not** attempt to:

- replace vanilla mutations
- automatically give every vanilla mutation its own Mutation Meddley branch tree
- make every external mutation a Mutation Meddley-owned mutation
- rewrite genotypes or subtypes
- rewrite faction reputation
- alter quests based merely on ecological classification
- automatically rebalance every vanilla mutation
- rewrite cybernetics or grant mutant characters unrestricted True Kin cybernetic installation
- patch every popular Qud mod directly
- require third-party mods to depend on Mutation Meddley
- directly serialize Mutation Meddley evolution state into foreign mutation classes
- globally modify external items because they are classified as mechanical, biological, conductive, etc.
- scan every object in a zone every turn
- perform reflection in combat hot paths
- use Harmony when read-only events, XML data, parts, or ordinary APIs can provide the needed information
- infer strong combat effects from weak semantic guesses

Compatibility takes priority over maximum cleverness.

---

# 4. Core architecture

The intended architecture is:

```text
Caves of Qud / third-party mods
        |
        | read-only observation
        v
Ecology Providers / Adapters
        |
        | normalized semantic facts + provenance
        v
Mutation Meddley Ecology Profiles
        |
        | relationship queries
        v
Mutation-local Mutation Meddley responses
```

The architecture must **not** become:

```text
external mod -> Mutation Meddley takes over external object -> Mutation Meddley rewrites it
```

The compatibility boundary is observation and interpretation.

> “What ecological capabilities are present?”

> “Does the actor have exactly this named mutation?”

# 6. Ecology Profile model

## 6.1 Actor Ecology Profile

An actor profile may describe:

- genotype
- subtype
- blueprint/classification traits
- body topology
- live mutations
- live cybernetics where safely observable
- currently equipped relevant technology
- active temporary effects
- Mutation Meddley branch identities
- dynamic environmental context

The actor profile is read-only with respect to foreign content.

## 6.2 Mutation Ecology Profile

Every relevant mutation may expose:

- stable semantic tags
- energy-domain tags
- body-plan implications
- environmental affinities
- explicit curated relationship IDs
- confidence/source metadata

A vanilla or third-party mutation does not become Mutation Meddley-owned because it has a profile.

## 6.3 Body Ecology Profile

Where verified body APIs permit it, body profiling should answer questions such as:

- number/class of locomotor limbs
- manipulators
- presence of unusual surface structures
- shell-like/armored structures
- wing/aerial structures
- burrowing structures
- synthetic/implanted components
- unusual head/sensory topology

Body profiling must avoid speculative body mutation.

## 6.4 Item / technology profile

Potential properties, only where safely observable:

- mechanical
- powered
- electronic
- conductive
- structural
- implanted
- cybernetic
- energy-storing
- heat-producing
- weaponized

External items remain untouched.

## 6.5 Target profile

Target profiles should be computed only when interaction requires them.

Potential uses:

- biological vs mechanical target behavior
- fungal target ecology
- conductive targets
- heavily structural targets
- swarm/colonial targets
- unusual sensory/predatory target classifications

Do not precompute target profiles for every object in a zone.

## 6.6 World / cell profile

A cell profile should normalize verified environmental facts:

- liquid characteristics
- temperature
- light
- gas/smoke
- terrain/traversal
- enclosure/open-space context where verifiable
- conductivity context
- technological/constructed context if safely inferable

# 7. Integration tiers

A tiered integration model is mandatory.

## Tier 0 — Unknown

Mutation Meddley does not understand the content.

Behavior:

- no crash
- no warning spam
- no strong assumptions
- no strong synergy
- content remains neutral

Unknown must be a valid steady state.

## Tier 1 — Inferred ecology

Mutation Meddley can derive broad traits through verified, generic data.

Examples:

- obviously mechanical object
- multi-limbed body plan
- demonstrably saline environment
- mutation with a verified broad category

Tier-1 data may support **soft ecology**:

- UI description
- clue flavor
- low-impact resource generation modifiers
- discovery eligibility
- environmental recognition

Tier-1 inference should not trigger large combat verbs automatically.

## Tier 2 — Curated adapter

Mutation Meddley explicitly knows the content and has documented behavior for it.

Examples:

- vanilla `Electrical Generation`
- vanilla `Multiple Legs`
- known cybernetic category
- known liquid type
- curated vanilla creature archetype

Tier-2 may support **hard ecology**:

- resource conversion
- reactive verbs
- strong branch interactions
- special discovery conditions
- triad participation

## Tier 3 — Cooperative external adapter

Another mod or compatibility pack explicitly declares how its content should participate.

This can permit deeper interactions while preserving optionality.

Tier-3 integration must remain harmless when either mod is absent.

---

# 8. Soft ecology versus hard ecology

This distinction is central to compatibility.

## 8.1 Soft ecology

Soft ecology may be driven by generic semantic recognition.

Examples:

- hidden-adaptation progress eligibility
- environmental affinity
- minor generation/retention changes
- clue text
- mutation information text
- broad target classification

Soft ecology should be balance-conservative.

## 8.2 Hard ecology

Hard ecology includes:

- bonus damage
- major healing
- strong resource conversion
- additional reactions
- large defensive effects
- coordinated triad spends

Hard ecology requires a curated relationship or cooperative adapter.

Rule:

> **Generic semantic recognition provides breadth. Curated verbs provide power.**

---

# 9. Provenance model

Every semantic trait must be explainable.

Instead of storing only:

```text
CONDUCTIVE = true
```

DEV diagnostics should be able to report:

```text
CONDUCTIVE
- Brineborn / Wellspring Flesh
- saline cell
- Chrome Marrow adapter
```

A semantic fact should therefore retain or be reconstructible from:

- source type
- source ID
- integration tier
- provider/adapter ID
- confidence level where relevant

This is required for debugging third-party mod interactions.

---

# 10. Conflict resolution

Different providers may disagree.

Semantic resolution must be deterministic and independent of incidental load order whenever possible.

Recommended precedence:

1. explicit deny/override from a curated Mutation Meddley rule
2. curated Mutation Meddley adapter
3. explicit cooperative third-party provider
4. generic inference

Conflicting facts must be inspectable in DEV mode.

Do not allow silent “last provider wins” behavior to become the default.

# 20. Relationship rule engine

By `1.1.0`, raw pairwise hard-coded checks will not scale indefinitely.

Introduce a conservative declarative relationship layer.

Conceptual examples:

```text
CONDUCTIVE + ELECTRICAL + WET
    -> conductivity ecology eligible

FUNGAL + HOT
    -> fungal thermal stress eligible

STRUCTURAL + BURROWING
    -> subterranean reinforcement eligible

REGENERATIVE + CHROME_HIGH_STRAIN
    -> unstable regeneration ecology eligible
```

The relationship engine should answer:

- is a relationship eligible?
- which sources satisfy it?
- what integration tier supports it?
- what intensity, if any, is available?

It should **not** directly apply arbitrary combat effects.

Mutation classes remain responsible for their own effects.

---

# 21. Optional ecological intensity

Most tags remain boolean.

A small number may benefit from bounded intensity.

Potential examples:

- `STRUCTURAL: 1..3`
- `CONDUCTIVE: 1..3`
- `FUNGAL: 1..3`

Intensity must not become a hidden 0–100 spreadsheet.

Add intensity only when:

- multiple independent sources meaningfully stack
- gameplay already needs degree rather than presence
- UI/DEV diagnostics can explain it
- balance tests can constrain it

---

# 22. Universal ecological discovery

Hidden-adaptation discovery can increasingly depend on semantic profiles rather than exact named mutations.

Example:

Instead of requiring one specific electrical mutation, a secret may require:

- strong conductive context
- repeated electrical interaction
- a compatible branch

That conductive context could come from:

- Storm Organ
- Electrical Generation
- a cooperative modded electrical mutation
- a cybernetic source
- environment/equipment where appropriate

Strong secrets may still require a named partner when their identity depends on it.

The goal is flexibility, not total genericization.

---

# 23. Species/body-specific clue text

Ecology Profiles can support contextual clue wording without changing the underlying trigger.

Example Chrome clue variants:

Structural body:

> Your frame has begun accepting manufactured load as though it were bone.

Fungal body:

> Filaments have found purchase inside the machine seams.

Colonial body:

> Something in the parliament has begun assigning work to the gears.

This should be used selectively. It is flavor amplification, not a requirement to write combinatorial prose for every tag.

---

# 24. Public compatibility API

`1.1.0` should establish the first supported external integration contract.

## 24.1 Goals

Allow another mod or compatibility pack to:

- declare semantic traits for known content
- provide an Ecology Profile contribution
- identify a custom environment/liquid/creature/mutation category
- declare optional relationship metadata
- query selected active Mutation Meddley ecology safely

## 24.2 Optionality

A third-party mod should not need Mutation Meddley installed merely to load.

Preferred approaches:

- loose metadata/XML where possible
- string/ID based registration where safe
- optional provider discovery
- reflection only during low-frequency registration if no safer mechanism exists and only after verifying failure behavior

Do not require direct assembly references for simple tag declaration unless there is no practical alternative.

## 24.3 Namespace rules

External provider IDs should be namespaced.

Mutation Meddley internal identifiers retain the `MutationMeddley_` prefix.

## 24.4 API stability

Once public, the provider contract becomes a compatibility responsibility.

Do not expose unstable internal resource implementation details unnecessarily.

---

# 25. External compatibility packs

Specific third-party integrations should be isolated from the core whenever practical.

A compatibility pack may map:

- external mutation IDs
- external creature IDs
- traits
- curated relationships
- optional clue/discovery participation

Rules:

- absent external mod -> adapter does nothing
- absent Mutation Meddley -> external mod should still work
- no missing-type crashes
- no hard dependency unless explicitly documented
- adapters remain individually disableable where feasible

`1.1.0` should validate the architecture with only a small number of test adapters rather than trying to support every known mod immediately.

---

# 26. Per-mod / per-layer opt-out

Compatibility requires a safety valve.

Candidate settings:

- Vanilla ecology integration: enabled by default
- Generic inferred external ecology: enabled by default or conservative default after testing
- Curated external adapters: enabled by default when detected
- Third-party provider API: enabled
- DEV ecology diagnostics: disabled by default

If an external mod behaves unexpectedly, the player should be able to disable inferred integration without disabling Mutation Meddley itself.

Settings must remain controller-accessible if exposed in normal game UI.

---

# 27. Existing Mutation Meddley migration toward semantics

`1.1.0` should audit existing named checks.

For every check such as:

- Multiple Legs
- Quills
- Regeneration
- Amphibious
- Electrical Generation
- Phasing
- Heightened Hearing
- Burrowing Claws

classify it as:

### Keep named

The exact vanilla mechanic is required.

### Convert to semantic

The design actually cares about a capability, e.g. `MULTI_LIMBED` or `REGENERATIVE`.

### Hybrid

Exact vanilla partner gets a curated hard interaction, while semantically similar content gets soft ecology.

The migration must preserve existing `1.0` gameplay unless intentionally documented.

---

# 28. No ownership of external content

This is an explicit engineering contract.

Mutation Meddley may say:

> “This mutation contributes a regenerative ecology trait.”

It must not silently treat that foreign mutation as a Mutation Meddley-owned evolving mutation.

Do not:

- write branch state into foreign classes
- rename external mutations
- mutate foreign serialized fields
- replace external activated abilities
- remove foreign effects
- assume external implementation details remain stable

External content is context.

# 30. Caching and performance architecture

Universal ecology is unacceptable if implemented as repeated global scanning.

Profiles should be divided by update frequency.

## 30.1 Stable profile

Changes rarely:

- genotype
- subtype
- blueprint traits
- stable mutation identity information

Cache aggressively.

## 30.2 Body/equipment profile

Changes on:

- body mutation
- limb change
- equipment change
- cybernetic change

Recompute only when invalidated.

## 30.3 Dynamic actor profile

Changes frequently:

- temporary effects
- stances
- Mutation Meddley resources
- current environmental relationship

Compute narrowly and avoid unnecessary allocation.

## 30.4 Environment profile

Cache per current cell where safe.

Invalidate when:

- actor moves
- cell state changes through known events
- relevant liquid/gas/temperature/light changes

Do not assume environment immutability.

## 30.5 Target profile

Compute only when a mutation actually needs target semantics.

Never preprofile every object in a zone each turn.

# 31. Event and patching policy

Preference order:

1. ordinary Qud event interfaces
2. parts/mutations
3. XML/data inspection
4. verified helper APIs
5. low-frequency optional provider registration
6. Harmony only as a last resort

Any Harmony proposal must document:

- why ordinary APIs are insufficient
- exact target method/version
- failure behavior when another mod also patches it
- rollback plan
- runtime performance impact

If a compatibility feature requires dangerous global patching, cut the feature before compromising the integration layer.

# 33. Qud version-update procedure

Broad integration increases sensitivity to upstream changes.

After a Qud update:

1. do not edit code immediately
2. deploy the unchanged latest Mutation Meddley build
3. run a fresh Qud compile
4. inspect warnings/errors
5. validate mutation IDs and provider assumptions
6. run Ecology Inspector on representative mutations, creatures, liquids, body plans, and technology
7. compare environment predicates
8. only then change implementation

Do not infer an API break from unrelated third-party mod errors.

# 34. Implementation phases

## Phase 0 — Freeze `1.0.x`

Acceptance:

- `1.0.x` production contracts pass
- no major save bug
- no severe performance issue
- nine-system ecology is stable

## Phase 1 — Semantic taxonomy design freeze

Before code:

- finalize initial traits
- remove unused speculative traits
- classify which traits are boolean vs intensity-capable
- define provider precedence
- define integration tiers

## Phase 2 — Ecology Profile core

Implement:

- profile data structures
- provenance
- stable/dynamic sections
- safe unknown handling
- deterministic conflict resolution

No broad vanilla adapter work until profile tests pass.

## Phase 3 — Provider architecture

Implement:

- built-in provider interface
- curated adapter registration
- optional third-party registration path
- absence-safe behavior
- provider diagnostics

## Phase 4 — Environment/world profile

Consolidate:

- wet
- saline
- hot/cold
- lit/dim/dark
- smoke/gas
- hostile traversal

Then add new verified environment semantics.

## Phase 5 — Vanilla mutation catalog

Profile every vanilla mutation.

For each:

- tags
- provenance
- tier
- test

Only after catalog completion begin broad semantic migration of existing pair checks.

## Phase 6 — Body/genotype/subtype profile

Implement verified read-only body and origin semantics.

## Phase 7 — Creature/target profile

Add representative creature categories and target-time profiling.

## Phase 8 — Liquid profile

Add liquid-property semantics and migrate Brine/Storm/Chrome/Mycelial relationships where safe.

## Phase 9 — Technology/cybernetic profile

Generalize verified `0.9` machine findings.

# 37. Performance contract

A `1.1.0` profile system must not noticeably degrade ordinary Qud play.

Prohibited patterns:

- full-zone object profiling every turn
- rebuilding stable actor traits on every event
- reflection in damage handlers
- unbounded provenance allocations in hot paths
- repeatedly scanning the full mutation collection when a cached stable profile suffices
- calculating target ecology without an actual interaction

Stress target:

- nine Mutation Meddley systems
- multiple vanilla mutations
- body-plan changes
- several active ecology relationships
- a populated combat zone
- 1,000-cell traversal
- repeated environmental transitions
- no meaningful stutter attributable to Ecology Profile calculation

# 38. Save compatibility

Most external ecology should be derived rather than serialized.

Serialize only when necessary for Mutation Meddley-owned history/discovery.

Rules:

- external traits recompute from live content on load
- no external object is modified to store MM profile state
- old `1.0.x` saves load without ecology-profile fields
- missing provider on load safely removes that provider's derived traits
- returning provider recomputes traits
- hidden discoveries already earned remain preserved according to existing MM persistence rules

# 44. Final design principle

`1.1.0` should make Mutation Meddley capable of understanding the wider world without attempting to own it.

The hierarchy is:

1. **Qud and other mods remain authoritative over their own content.**
2. **Mutation Meddley observes that content.**
3. **Ecology Providers translate observations into semantic meaning.**
4. **Ecology Profiles normalize that meaning.**
5. **Relationship queries decide what is ecologically relevant.**
6. **Mutation Meddley-owned systems decide how they react.**

The compatibility promise is therefore:

> **Mutation Meddley should become better when more strange content exists around it, without requiring that strange content to surrender control to Mutation Meddley.**

That is the foundation for truly merging mutations, bodies, lineages, creatures, environments, technology, and compatible mods into one living Caves of Qud ecology.
