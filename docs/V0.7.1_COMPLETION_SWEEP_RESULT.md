# Mutation Meddley v0.7.1 — Completion Sweep Result

This document records the final static/structural state of the v0.7.1 completion sweep before the authoritative Caves of Qud compile and runtime gate.

The governing design documents remain:

- `V0.7.1_PLAYER_AGENCY_RECOVERY_PLAN.md`
- `V0.7.1_QUD_NATIVE_STABILIZATION_SWEEP.md`
- `V0.7.1_QUD_NATIVE_STABILIZATION_IMPLEMENTATION.md`

## Completed in the completion sweep

### Qud-shaped ability ownership

Mutation-specific primary abilities are mutation-owned. The adaptive mutation base registers each mutation's primary command, synchronizes the activated ability, removes it on mutation removal/dormancy, and replaces it when the rank-3 identity changes.

`Mutation Meddley Biology` remains a single player-global aggregate inspector. It does not register the five mutation action commands.

### Primary action execution no longer depends on Biology

The gameplay transaction is centralized in `MutationMeddley_PrimaryActionService` and reads/writes mutation state through `MutationMeddley_StateEnvelopeAccess`.

The service does not require a `MutationMeddley_BiologySupport` instance. Biology may be refreshed after a successful transaction when present, but absence of the inspector is not a prerequisite for the action transaction itself.

The mutation command path calls the action service directly. Biology is only used opportunistically to provide richer current-resource text when it is already available.

### Defensive new-game player handling

The player bootstrap has independent paths:

1. `PlayerMutator` installs Biology using the player object supplied by Qud's new-game lifecycle.
2. `CallAfterGameLoaded` repairs existing saves.
3. MM mutation registration/gain ensures the support on an established player.
4. MM mutation EndTurn provides a late repair pass.

A support part already installed by `PlayerMutator` is treated as a trusted player-UI marker before mutation-side code rechecks `IsPlayer()`. This specifically covers character-construction ordering where Qud has supplied the player object but `IsPlayer()` may not yet be observable to every mutation callback.

NPC mutation objects do not receive player UI support because mutation-side installation still requires either the existing player-only support marker or a positive player check.

### Shared action catalog

Primary action signature, name, rules, and base description are centralized in `MutationMeddley_PrimaryActionCatalog`.

The mutation lifecycle and Biology UI consume the same catalog, preventing branch-action names/rules from drifting between the bottom ability bar and Biology.

### Shared state-envelope access

Biology no longer contains its own parser/writer for the serialized evolution/resource state envelope.

`MutationMeddley_StateEnvelopeAccess` now owns read/write parsing used by the new action service and Biology bridge. Writes preserve selected evolution IDs, unknown metadata keys, and `statev=1`.

### Healing normalization

Historical concrete `ParentObject.Heal(...)` paths were routed through the Mutation Meddley shared healing helper. The repository preflight now requires the framework helper in `MutationMeddley_EvolvingMutationBase` to be the only direct `ParentObject.Heal(...)` location.

This makes rank-4/7/10 verb growth use one healing policy instead of leaving Carapace/Brine/Colony exceptions.

### Reaction telemetry correction

The 0.7.1 Biology descriptions were reconciled with the current resource-spend code:

- Wellspring automatic recovery spends Mend rather than pretending Reserve is the reaction cost.
- Saltglass reaction cost is 1 Bastion.
- Scouring Wake wording separates generation requirements from the actual stored-Wake contact spend.
- Furnace reaction reports Kiln as the spend, not Embers.
- Cinder reports Rush as the spend.
- Smoke reports Haze as the spend.
- deterministic readiness remains `100%`/`0%` where current state determines it.

No random proc chance was introduced merely for UI presentation.

### Passive/max-HP safety retained

The earlier v0.7.1 repair remains intact:

- fast-changing Brace does not alter Toughness/max HP;
- passive stat changes are collected as a desired snapshot;
- only actual final-value differences are committed to Qud's stat shifter.

### Evolution ability repair

`MutationMeddley_AbilityRepair` repairs stale saved Evolve GUIDs when the saved GUID no longer exists in `ActivatedAbilities`.

This is a migration/defense path for old saves and failed early v0.7.1 test builds.

### Automated repository gates

`.github/workflows/preflight.yml` now executes on `main`, `fix/**`, and pull requests.

It runs:

- `bash tools/check.sh`
- `python3 tools/check_completion_contract.py`
- shell syntax checks for all Bash helper scripts

The completion contract specifically rejects regression back to Biology-owned gameplay transactions or Biology-routed mutation command execution.

The exact completion-branch structural checks passed on GitHub Actions before merge preparation.

## Intentionally runtime-gated instead of guessed

The following are not safe to invent from static source inspection:

### Qud scripting compile

The installed Caves of Qud build remains the authoritative compiler. GitHub Actions does not contain the user's Qud assemblies and therefore cannot prove the exact scripting API compile.

### Adjacent ranged attack while engaged

The current contact classifier is intentionally conservative. A controlled runtime trace is required before adding an attack-type API that has not been verified against the supported Qud build.

### `TookDamage` versus `TookEnvironmentalDamage` duplication

A controlled environmental hit must establish whether one incident reaches both registered event names before any deduplication transaction is introduced.

### `DamageDispatched` branch semantics

Several branch effects intentionally distinguish successful damage dispatch from observed HP loss. The preflight lists all consumers so the runtime DEV trace can review them explicitly. No global semantic rewrite is justified without that trace.

### Loaded `StatShifter` cache behavior

The nonserialized applied-shift cache starts empty after reload. Runtime save/reload testing must prove Qud's restored `StatShifter` entries are updated idempotently rather than duplicated or oscillated.

### Environment predicates

Wet/saline/hot/smoky detection remains on the existing verified-enough heuristic layer for v0.7.1. Replacing it belongs to the v0.8 environment subsystem after exact APIs are proven.

## Authoritative runtime gate

After this branch is on `main`, the exact release candidate must pass on the user's installed Qud build:

1. `git pull --ff-only`
2. `bash tools/check.sh`
3. `python3 tools/check_completion_contract.py`
4. `bash tools/deploy.sh`
5. fully restart Caves of Qud
6. `bash tools/logs.sh`
7. require a fresh `Success :)` for Mutation Meddley
8. require `Mutations.xml` load with no MM runtime exception

Then perform the minimum new-game smoke test with vanilla Carapace + Carapace Evolution + Walking Colony:

- `Mutation Meddley Biology` exists immediately or is repaired by the mutation lifecycle before normal play proceeds.
- `Brace Shell` exists exactly once.
- `Redistribute Pressure` exists exactly once.
- rank-1/2 Carapace/Colony do not show Retune because no stance exists yet.
- one ordinary turn does not duplicate any of these abilities.
- rank-3 identity selection replaces the baseline primary action with one branch action and adds one Retune ability.
- save/reload reconstructs the same ability set exactly once.

The release then still needs the Tighten/max-HP regression test, deliberate-action transaction matrix, reaction telemetry check, controller-only Biology navigation, and controlled DEV damage-event traces documented in the stabilization plan.

## Completion definition

The static completion sweep is complete when the repository and CI enforce the intended architecture. The v0.7.1 release is complete only when the same exact commit passes the installed Qud compile and runtime gates above.
