# Mutation Meddley v0.9.0 — New Ecologies Expansion Plan

## Release thesis

`0.9.0` is the first major content-expansion release built on the systems established in `0.7.x` and deepened in `0.8.x`.

The release thesis is:

> **Prove that Mutation Meddley can scale from a small set of deeply interconnected mutations into a larger ecosystem without collapsing into flat bonuses, unreadable synergy spam, save instability, or untestable combinatorics.**

`0.9.0` should introduce **four new flagship mutations**, each with the same level of mechanical completeness as the existing roster:

1. **Storm Organ / Voltaic Anatomy** — electrical ecology.
2. **Mycelial Communion** — fungal / growth / decay ecology.
3. **Neural flagship** — cognition / perception / behavioral-pattern ecology.
4. **Chrome Marrow** — biomechanical / biological-machine ecology.

The release should not simply add content entries. Each new mutation must ship with:

- an immediately functional rank-1 baseline
- continuous mutation-rank progression
- three rank-3 identities
- two rank-6 specializations per identity
- rank-9 capstones
- unusual hidden adaptations
- two stance / operating-mode choices after rank 3
- a resource or state economy with clear build/spend behavior
- branch-specific liabilities
- curated pair synergies
- selected triad integrations
- non-spoiler hidden-discovery clues
- controller-readable mutation-screen information
- save/reload support using the existing evolution-state envelope
- explicit runtime tests against the exact supported Qud build

The central design requirement is that a new mutation must feel like a **complete organism**, not an expansion-pack bolt-on.

---

# 1. Prerequisite freeze

Implementation of `0.9.0` begins only after the `0.8.x` ecology pass has survived normal play without structural failures.

The following contracts are considered frozen unless runtime evidence demonstrates a bug:

- ranks **3 / 6 / 9** remain the qualitative evolution milestones
- ranks **2 / 5 / 8** remain maturity-growth points
- ranks **4 / 7 / 10** remain continuous verb-output growth points
- existing evolution choices remain persistent
- the serialized evolution-state envelope remains the save-state mechanism
- no existing public serialized field is renamed or removed
- normal gameplay requires no typing
- stance/evolution selection remains controller-usable
- non-adjacent attacks cannot consume close-contact resources
- bonus-damage recursion protection remains mandatory
- hidden rank-9 alternatives must be discovered before the rank-9 tier is spent
- dormant companion mutations contribute no active ecology
- pair and triad effects are still mutation-local in ownership
- world/environment detection must use verified Qud APIs or explicitly documented heuristics

`0.9.0` may add narrowly justified framework helpers, but it is not permission for a second rewrite of the core engine.

---

# 2. Scope

## 2.1 Target content volume

`0.9.0` targets:

- **4 new flagship mutations**
- **12 new rank-3 identities**
- **24 new rank-6 specializations**
- approximately **36 normal rank-9 endpoints**
- approximately **16 unusual hidden adaptations**
- roughly **20 curated new pair relationships**
- **8–10 new triads**
- one generalized ecology-history facility
- expanded hidden-discovery clue support
- machine / robotic classification helpers only where verified
- new liabilities designed alongside every branch
- no requirement that every mutation pair interact

This is already a very large release. The scope should not be increased merely because framework work finishes early.

## 2.2 Explicit non-goals

The first `0.9.0` pass does **not** include:

- a fully connected synergy graph
- a special effect for all 36 possible Mutation Meddley-to-Mutation Meddley pairs
- a global mutation-combo manager controlling all mutation internals
- full vanilla cybernetic-system replacement
- automatic True Kin cybernetic access for mutants
- speculative body-part creation/removal
- broad faction or quest content
- new procedural world regions
- dozens of new NPC species
- global vanilla mutation rebalance
- mandatory rank-10 evolution menus
- Harmony patching merely to make a planned mechanic easier
- unverified robotics, EMP, equipment-power, cybernetic, or corpse APIs
- permanent environmental-object spam without a verified lifecycle

# 3. Synergy topology policy

With nine major Mutation Meddley systems, exhaustive pair design becomes unmanageable.

Nine systems produce **36 possible internal pairings** before vanilla mutations, branches, stances, triads, hidden adaptations, terrain, and rank are considered.

Therefore:

> **Neutral relationships are valid and intentional.**

Every new mutation should have approximately:

- **3–5 strong Mutation Meddley relationships**
- **2–4 curated vanilla mutation relationships**
- **1–3 triad roles**
- several intentionally neutral combinations

A pair should only become a named mechanical synergy when it creates a distinct gameplay interaction.

A relationship does not qualify merely because the flavor pairing sounds interesting.

Every upgraded synergy must define:

- exact eligibility
- branch restrictions
- priming action
- resource/state affected
- spend or conversion condition
- payoff
- liability or limiting condition
- owning mutation
- scaling owner
- player feedback
- failure behavior
- save behavior
- regression tests

# 4. Shared ecology-history framework

## 4.1 Why it is needed

The current hidden-adaptation system can use individual persistent progress keys, but a roster of nine mutations and dozens of unusual adaptations will otherwise lead to repetitive one-off counter code.

`0.9.0` should introduce a small generalized behavior-history helper.

The goal is **not** to build a global achievement system.

The helper exists to record biologically meaningful repeated behavior used by mutation-local discovery logic.

Conceptually:

- advance a named history key
- read a named history key
- optionally clamp it
- preserve it inside the existing state envelope
- never expose exact counters during normal play
- allow DEV diagnostics to inspect exact values

Potential history categories:

- successful close-contact resource spends
- turns spent saline
- high-heat exposure
- heat-to-cold transitions
- electrical overload survived
- mechanical-enemy interactions
- resource conversions
- movement streaks
- stationary defensive turns
- heavy-strain turns
- synergy activations
- repeated use of a specific stance
- recovery under pressure
- environmental state changes
- successful adaptation swaps

## 4.2 Save rules

The history helper must:

- use the existing serialized state envelope
- introduce no new public persistent field unless unavoidable
- tolerate missing keys from old saves
- preserve unknown keys
- avoid key collisions through `MutationMeddley_` naming or mutation-local prefixes
- never reset ecology history on stance switching
- never reset history merely because the condition becomes inactive
- stop hidden-rank-9 progress after the corresponding tier is spent unless explicitly designed otherwise

# 5. Flagship mutation A — Storm Organ / Voltaic Anatomy

## 5.1 Core fantasy

The body has grown an organ system that treats charge, conduction, movement, and electrical violence as metabolic resources.

This must **not** be a replacement for vanilla Electrical Generation.

The mutation is about **routing electrical state**, not simply producing larger electrical attacks.

## 5.2 Core resource: Charge

Charge represents stored electrical potential available to the organism.

Possible sources, only after API verification:

- taking electrical damage
- successfully dealing qualifying electrical damage
- movement while under specific electrical conditions
- conductive wet/saline environments
- interaction with powered or mechanical entities
- synergy conversion from other Mutation Meddley resources

Charge should have:

- a baseline cap
- rank-sensitive output but not necessarily rank-sensitive cap
- branch-specific generation rules
- overload behavior if the player pushes beyond safe operating patterns

## 5.3 Core liability: Overload

High Charge should be powerful but unsafe.

Overload should not be arbitrary random self-damage.

Preferred consequences:

- forced Charge loss
- temporary inability to generate Charge efficiently
- reduced defensive stability
- increased Strain if Chrome Marrow is present
- branch-specific lockout
- adverse interaction with wet/saline conditions
- a short forced grounding / discharge state

## 5.4 Rank-1 baseline

Baseline Storm Organ should work before any identity is selected.

Proposed baseline loop:

- electrical exposure or another verified qualifying trigger stores limited Charge
- incoming damage while Charge is available can consume a small amount for a defensive electrical reflex
- a simple offensive or retaliatory event can expend Charge
- rank 2 visibly matures the baseline

The baseline must be observable without requiring Electrical Generation.

## 5.5 Rank-3 identity 1 — Galvanic Predator

Fantasy:

> Charge becomes hunting momentum.

Gameplay:

- movement and close-contact combat matter
- repeated pursuit improves Charge routing
- Charge is spent through melee/contact verbs
- stationary play is less efficient

Possible modes:

### Hunt Current
Build and preserve Charge while moving toward hostile contact.

### Arc Bite
Spend Charge more aggressively on successful close contact.

Core liability:

- loss of efficiency while stationary
- aggressive spending can create Overload

### Rank-6 specialization A — Relay Tendons

Focus:

- pursuit continuity
- movement-linked Charge retention
- repeated contact

### Rank-6 specialization B — Arc Jaw

Focus:

- heavier contact discharge
- larger spends
- more Overload risk

### Rank-9 normal capstones

- **Storm Pursuit**
- continuous pursuit transforms Charge retention into reliable contact pressure

- **Thunder Maw**

### Hidden rank-9 adaptations

Modes:

# 8. Flagship mutation D — Chrome Marrow

## 8.1 Core fantasy

> Your tissues do not reject machinery. They digest its principles.

Chrome Marrow is not merely “mutant cybernetics.”

It is a mutation where the distinction between anatomy and machinery becomes biologically unstable.

The mutation must remain functional even if no safe API exists for direct True Kin cybernetic installation.

Its mechanics should be based on verified technological interactions, not an assumption that mutants receive access to the cybernetics screen.

## 8.2 Core resources: Integration and Strain

### Integration

Integration measures how completely biological and mechanical behavior are operating as one system.

Possible verified sources:

- electrical events
- powered equipment state
- mechanical enemies
- tinkered equipment interactions
- heavy structural pressure
- Chrome-specific branch verbs
- Storm Organ synergy
- Carapace / Living Crystal structural interactions

### Strain

Strain measures rejection, heat, feedback, actuator stress, seizure, and interface instability.

The fundamental Chrome Marrow rule:

> **Integration is power. Strain is the price of using too much power too quickly.**

Strain must not be a simple “bad meter.”

Branches should interact differently with it:

- some avoid it
- some vent it
- some convert it
- some deliberately operate near dangerous thresholds

## 8.3 Strain bands

Conceptual bands:

### Stable
Normal function.

### Loaded
Advanced mechanics receive stronger payoff.

### Redline
Strong output with clear operating penalties.

### Critical
A forced biomechanical consequence becomes possible or inevitable.

Preferred Critical consequences:

- forced venting
- temporary Integration collapse
- reduced movement
- inability to use a Chrome reaction for a short period
- temporary defensive instability
- branch-specific seizure / lock state

Avoid:

- arbitrary repeated random self-damage
- permanent item destruction
- save-bricking body changes

## 8.4 Healing vs maintenance

Chrome Marrow should distinguish:

- **HP damage** — injury to the organism
- **Strain** — instability in the flesh-machine interface

Normal healing can restore HP.

It should not automatically erase Strain.

This creates a two-axis maintenance problem.

Regeneration may let the player survive physical damage while still leaving them dangerously over-integrated.

That difference is a major part of the mutation's identity.

## 8.5 Rank-1 baseline

Baseline Chrome Marrow should:

- build limited Integration from a safe verified technology/electrical/structural trigger
- allow a small Integration spend for defense or stabilization
- generate a small amount of Strain when pushed
- give the player a way to reduce Strain without requiring another mutation
- visibly mature at rank 2

No identity should be required for the mutation to function.

# 15. Liability design rules

`0.9.0` should treat liabilities as standard mutation design, not optional flavor.

Every rank-3 identity must answer:

- What does this path want?
- What situation weakens it?
- What resource can be mismanaged?
- What player behavior creates risk?
- How does the liability interact with its stance?
- Can the player mitigate the liability?
- Can the player deliberately exploit it?
- Does the liability remain relevant after rank 9?

Bad liability:

- unconditional -2 DV
- arbitrary random damage
- permanent inconvenience unrelated to the branch

Good liability:

- break your pursuit and lose learned prey state
- leave rooted terrain and lose fungal network
- remain dry and lose saline ecology
- overcharge and force grounding
- redline Chrome and accumulate Strain
- change sensory pattern and disrupt neural Signal

The liability should reinforce identity.

# 26. Balance rules

## 26.1 New mutations must not power-creep the originals

A new system cannot be better merely because it is newer.

Compare:

- startup cost
- rank investment
- action economy
- setup time
- reliability
- damage
- mitigation
- mobility
- environmental dependency
- liability severity
- synergy dependence

## 26.2 Pair synergies must not become mandatory

A flagship must remain useful alone.

A pair can:

- change routing
- unlock an alternative operating style
- mitigate a liability
- create a risk/reward conversion

It should not simply double output.

## 26.3 Triads must require real setup

A triad should feel powerful because:

- three specific paths align
- their resources coordinate
- the player performs the intended loop

Not because owning three mutations grants permanent +5 AV and +20 Quickness.

## 26.4 Hidden adaptations must be alternatives

Unusual adaptations should:

- reward behavior
- redirect the branch
- create a strange build identity

They should not be secret mandatory upgrades.

# 32. Final design principle

The purpose of `0.9.0` is not to make Mutation Meddley larger for its own sake.

It is to prove that the mod can support a broad mutation ecosystem while preserving the traits that make the project distinctive:

- mutation points always matter
- branches change how the player acts
- previous biology remains relevant
- the world matters
- liabilities matter
- strange combinations are discoverable
- synergies change verbs rather than merely numbers
- secrets reward behavior
- anatomy and environment are part of the build
- controller play remains practical
- save stability is respected
- implementation remains grounded in verified Qud APIs

The four new flagship families should therefore feel like new biological philosophies:

- **Storm Organ:** electricity is metabolism and routing.
- **Mycelial Communion:** growth and decay are territory.
- **Neural ecology:** experience becomes pattern.
- **Chrome Marrow:** machinery becomes anatomy.

Chrome Marrow's central question should remain the defining thematic test:

> **At what point does a machine implanted into living tissue stop being equipment and start being an organ?**

Mutation Meddley should answer that question through what the player actually does with the body.
