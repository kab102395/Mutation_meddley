# Mutation Meddley v0.7.1 — Player Agency & Biological Telemetry Recovery Plan

## Release thesis

`0.7.1` is a recovery release driven by the first serious hands-on playtests of `0.7.0`.

`0.7.0` established continuous rank progression and functioning stored-state mutation loops, but play exposed a structural usability failure: the code often knew far more about the character's biology than the player did. Brace, Pressure, Stress, Reserve, Embers, and branch-specific currencies were mechanically real yet inadequately visible; many meaningful spends happened automatically in event handlers; exact reaction eligibility was difficult to reason about; and passive stat refreshes were aggressive enough to destabilize health-related presentation.

The release thesis is:

> **If the character's body knows something, the player should be able to know it. If the character can deliberately do something, the player should be able to command it.**

A companion rule is:

> **Automatic biology may remain automatic, but it must never be invisible biology.**

This is intentionally a large patch release. It corrects player-facing assumptions discovered through real play rather than adding unrelated feature scope.

## 1. Playtest failures being corrected

### 1.1 Hidden tactical state

Current live state includes:

- Carapace Evolution: Brace, Impact, Heat, Mire, Rime
- Living Crystal: Stress, Cadence, Dawn, Dusk, Release
- Brineborn: Reserve, Mend, Bastion, Wake
- Ash Metabolism: Embers, Kiln, Rush, Haze
- Walking Colony: Pressure, Stitch, Scout, Delegated Load, movement streak

These are tactical resources and must be inspectable as `current/max` without reading source code.

### 1.2 Too much automatic spending

Automatic biological reflexes remain valid, but any mechanic whose timing is a meaningful player choice needs a deliberate activated use. Resources should be gameplay state, not merely ammunition consumed by hidden event handlers.

### 1.3 Reaction opacity

Every important automatic reaction needs to expose:

- trigger
- current probability
- cost
- effect
- relevant limit/condition
- current blocked state where determinable

Existing deterministic reactions remain deterministic. `0.7.1` does not add randomness just to justify displaying percentages. Eligible deterministic reactions show `100%`; blocked reactions show `0%` when current state is sufficient to determine that.

### 1.4 Tighten Carapace / max-HP instability

Playtesting showed Toughness and maximum HP oscillating around use of vanilla `Tighten Carapace`. The immediate Mutation Meddley causes are:

- unevolved Carapace Evolution used `Brace > 0` to grant temporary Toughness
- Toughness changes maximum HP
- Brace is a fast-changing combat resource
- the passive refresh path previously zeroed Mutation Meddley stat shifts and then rebuilt them

`0.7.1` therefore removes Brace-driven Toughness and replaces destructive zero/reapply refresh with desired-state/delta commit.

## 2. Non-negotiable player contract

Before `0.7.1` is considered stable:

1. Every relevant resource has current/max presentation.
2. Every owned Mutation Meddley mutation appears in one universal Biology interface.
3. Every strategically deliberate mutation action has a normal Qud activated ability.
4. The same action can be invoked from the Biology interface.
5. Ability-bar and Biology invocation share one implementation.
6. Genuine reflexes remain automatic reactions.
7. Every automatic reaction shows its trigger.
8. Every automatic reaction shows its exact current probability wherever the state can determine it.
9. Deterministic eligible reactions explicitly show `100%`.
10. Blocked reactions show `0%` when the reason is presently knowable.
11. Reaction resource costs are visible.
12. Active resource costs and energy costs are visible.
13. Resource generation and decay rules are visible.
14. Current Mutation Meddley stat contributions are inspectable by source mutation.
15. Current stance and evolution path are visible.
16. Inspection is free and consumes no turn.
17. Successful deliberate actions consume their normal action energy.
18. Cancelled or invalid actions spend no resource and no energy.
19. Everything works with controller and no typing.
20. Existing `0.7.0` evolution state and hidden-discovery state remain compatible.

## 3. Universal Mutation Meddley Biology ability

A player with at least one Mutation Meddley mutation receives:

`Mutation Meddley Biology`

It is a free inspector/navigation ability. It spends no resource and no energy.

The top-level interface lists only owned Mutation Meddley mutations and displays:

- rank
- evolution path
- stance
- relevant current/max resources

Global pages provide:

- current Mutation Meddley modifiers
- all automatic reactions
- active pair synergies/triads

The Biology interface is not a second implementation of gameplay. Selecting an active action from it routes into the exact same underlying action used by the ordinary activated-ability button.

## 5. Resource visibility strategy

A custom Harmony-patched HUD is explicitly out of scope for this recovery patch.

The first supported implementation keeps resources naturally accessible through native ability surfaces:

- the Biology ability description contains a compact snapshot of all owned MM resources
- each mutation's branch-aware primary action description begins with that mutation's current resource snapshot
- the Biology menus provide complete current/max and flow information

If a later verified Qud API exposes a clean compact HUD/status extension, these same resource providers can feed a more health-like meter strip without changing gameplay state.

## 6. Mechanic taxonomy

Every mechanic is classified as one primary type:

- **Passive** — always-on or conditionally recomputed biology; no button
- **Resource** — tracked biological state; visible current/max
- **Active** — player chooses timing; activated ability
- **Reaction** — automatic event response; exact telemetry
- **Stance** — persistent operating configuration; Retune ability
- **Evolution** — permanent 3/6/9 choice; Evolve ability

A resource is not an ability. A deliberate thing the player does with a resource is.

## 7. Action-bar policy

To avoid action-bar spam, each current Mutation Meddley family receives one branch-aware primary deliberate action. The name/function changes at rank-3 identity selection rather than continually adding new buttons.

The Biology menu also exposes that action, making rare use possible without forcing the player to bind every command manually.

## 13. Reaction probability policy

`0.7.1` makes probability a first-class player-facing value.

For existing deterministic reactions:

- eligible + resource available -> `100%`
- required resource absent -> `0%`
- complex environmental/contact trigger -> `100% when the documented trigger qualifies`

Future probabilistic reactions must use one source-of-truth chance calculation shared by gameplay and UI. No tooltip may calculate a different percentage than the actual roll path.

## 14. Passive-stat transaction repair

Old refresh behavior:

1. set every known MM shift to zero
2. recompute
3. reapply final values

New refresh behavior:

1. clear the desired-value dictionary only
2. mutation logic builds desired shifts
3. shared/static-freeze logic contributes desired shifts
4. compare desired against last applied values
5. call `StatShifter.SetStatShift` only when the final value actually changed
6. remove stale shifts once when a contribution genuinely disappears

This prevents unchanged Toughness/max-HP contributions from briefly disappearing during movement/damage refreshes.

## 15. Brace/Toughness correction

Unevolved Carapace Evolution no longer uses live Brace to add Toughness.

Baseline remains:

- `+1 AV`

Brace-active temporary defense becomes:

- `+1 DV`

Continuous rank maturity may still add persistent Toughness because rank progression is infrequent and deliberate rather than a per-turn resource oscillation.

## 16. Duplicate refresh containment

Concrete mutations still contain historical calls to `MutationMeddley_RefreshPassiveEffects()`.

In `0.7.1`, these intermediate calls now only rebuild desired state and do not immediately mutate Qud stats. The Adaptive base performs the authoritative final commit after shared contributions are included.

This contains the current risk without combining the player-agency recovery patch with a broad five-mutation event rewrite.

## 17. Stance re-selection

- cancel: free
- select already-current stance: free
- actually change stance: 1000 energy

## 18. Biology support lifecycle

The Biology support part is attached to:

- new players through a player mutator
- existing saves after load through a load callback

The support part owns:

- Biology inspector ability
- branch-aware primary action abilities
- live ability-description telemetry

Ability synchronization removes obsolete actions when a branch changes and avoids recreating abilities merely because a meter changed.

## 19. Action transaction policy

Every deliberate action follows:

1. validate mutation is active
2. validate resources/state
3. validate healing need or destination cap
4. if invalid: show failure and spend nothing
5. commit resource conversion/spend
6. perform effect
7. refresh mutation snapshot
8. refresh ability telemetry
9. spend 1000 energy
10. emit one meaningful message

Inspection never enters this transaction.

## 20. Save compatibility

`0.7.1` continues using the existing `MutationMeddley_EvolutionState` envelope.

The Biology support state helper:

- preserves selected evolution IDs
- preserves unknown metadata keys
- preserves hidden progress
- preserves stance
- preserves `statev=1`
- modifies only the requested resource key

No existing public mutation-state field is renamed or removed.

## 21. Controller contract

All new interaction uses controller-safe native option-list style navigation:

- directional navigation
- confirm
- cancel
- scrolling
- no text input
- no mouse-hover requirement
- browsing is free
- selecting a real action from Biology executes its normal cost

## 22. Message-log policy

Do not spam routine resource increments such as every +1 Pressure/Brace/Ember.

Messages are reserved for:

- deliberate action use
- meaningful reactions
- unusual adaptation discovery
- major biological state transitions

Live telemetry carries the routine meter state.

## 30. Permanent process change

The playtest failure behind `0.7.1` becomes a permanent rule:

> **Implementation completion is not feature completion.**

Every future resource must ship with:

- current/max presentation
- generation/decay explanation
- deliberate action where appropriate
- reaction metadata
- exact probability
- cost
- controller interaction
- useful feedback
- modifier provenance

Every future branch must be playable from the game UI rather than requiring source knowledge. Short real-play checkpoints happen during implementation, not only after a large systems pass is declared complete.
