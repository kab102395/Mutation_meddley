# Mutation Meddley v0.7.1 — Qud-Native Stabilization and Bug Sweep

## Purpose

This document defines the second stabilization pass for `0.7.1` after hands-on playtesting exposed two classes of problems:

1. player-facing systems could compile without actually surfacing in normal Qud play, and
2. several mechanics were technically functioning but were wired in ways that did not follow the natural ownership/lifecycle patterns used by Qud mutations and activated abilities.

This is not a content expansion. It is an architectural and behavioral hardening pass.

The release rule is:

> Mutation-owned behavior should be owned by the mutation. Player-global inspection should be owned by one player support part. Shared framework code should coordinate, not impersonate concrete mutations.

The corresponding player rule is:

> If a Mutation Meddley mutation can deliberately do something, that mutation owns a normal Qud activated ability for it. If the mod wants to summarize the whole body, the Biology inspector reads those mutations rather than reimplementing them.

## Qud-native reference points

The pass is intentionally aligned to the documented Qud patterns that are already known to work in the supported build:

- individual mutations are `BaseMutation`/parts and naturally own their mutation-specific activated abilities
- mutation abilities are added/removed through the activated-ability surface and command events
- 1000 energy is one normal action; inspection remains free
- `PlayerMutator` is a new-game hook, while `CallAfterGameLoaded` is the loaded-save fallback
- generic player support may be an ordinary player-attached part, but concrete mutation mechanics should stay in concrete mutations
- unique commands/classes remain `MutationMeddley_` prefixed
- existing serialized mutation fields remain stable
- Harmony is not required for any issue in this sweep

## Scope

### In scope

- activated-ability ownership and lifecycle
- Biology bootstrap hardening
- resource/action/reaction single-source-of-truth
- removal of duplicated state parsing and duplicated cap calculations
- mutation-specific action implementation moved out of the Biology support part

- Spiteful Wall brace behavior contradiction

- Harmony patches

## Audit findings

### Finding A — active action ownership is backwards

The first `0.7.1` implementation placed all five mutation action buttons in `MutationMeddley_BiologySupport`.

That is structurally weaker than the existing Evolve/Retune implementation. Evolve/Retune worked because the mutation that owns the behavior also owns the ability lifecycle. The new actions depended on a separate support part being installed at exactly the right time.

**Correction:** every adaptive mutation owns its own primary action ability. Biology only discovers and invokes it.

### Finding B — Biology duplicates concrete mutation state logic

The Biology support currently parses `MutationMeddley_EvolutionState` itself and reproduces resource keys, cap formulas, evolution checks, and environmental conditions.

This creates two implementations of the same state contract.

Confirmed drift already exists:

- Ash Metabolism's real Ember maximum includes the Photosynthetic Skin/light modifier, while the Biology copy omitted it
- Walking Colony's real Pressure maximum uses semantic-tag logic, while the Biology copy approximated the same rule with a short list of mutation names
- Living Crystal's effective Cadence display duplicated only part of the real Cadence modifier path

**Correction:** concrete mutations expose read-only telemetry methods. Biology never parses mutation persistence or computes mutation caps itself.

### Finding C — Biology owns mutation-specific verbs

The support part currently contains a large switch/if tree for Carapace, Crystal, Brine, Ash, and Colony action effects.

That violates the project architecture rule that mutation-specific behavior belongs in the concrete mutation.

**Correction:** concrete mutation methods implement their own deliberate actions; the adaptive base provides only generic ability registration, action transaction, energy handling, and Biology-facing wrappers.

### Finding D — useless Retune abilities exist before a stance exists

`MutationMeddley_AdaptiveMutationBase` currently creates Retune immediately, even at rank 1 when there is no rank-3 identity and therefore no stance choice.

This creates an ability whose only result is “no stance available.”

**Correction:** Retune exists only when the mutation is functionally active and `GetModeChoices()` returns at least one real stance.

### Finding E — action lifecycle is not self-healing enough

A saved ability GUID may be stale, the action identity may change at rank 3, Carapace Evolution may become dormant, or an older save may have no new action GUID at all.

**Correction:** each mutation performs an idempotent action synchronization at safe lifecycle points. The action GUID/signature are stored in the existing evolution metadata envelope rather than adding new public serialized fields.

### Finding F — adding more public serialized fields is avoidable

Qud's normal binary serialization is sensitive to class field layout over mod versions. The existing public fields are preserved.

**Correction:** no new public serialized fields are added to the established mutation classes. New primary-action identity is persisted inside the already-stable `MutationMeddley_EvolutionState` envelope.

### Finding G — Biology support public fields must remain stable

The first `0.7.1` Biology part already introduced public action GUID/signature fields. Removing them immediately could create save migration problems for anyone who created a save with the test build.

**Correction:** preserve those legacy public fields in the Biology support class but stop using them for action ownership.

### Finding H — duplicated partial support files make ownership unclear

The Biology support was split across nine partial files containing state parsing, action implementation, cap formulas, reaction descriptions, and menus.

The split hid the more important problem: a player-global support part had become a second mutation engine.

**Correction:** consolidate Biology into one focused support implementation plus the lifecycle installer. Delete obsolete mutation-engine partials.

### Finding I — Spiteful Wall contains contradictory brace behavior

The concrete Carapace turn processor still discards brace simply for remaining engaged, while the shared static-freeze patch simultaneously tries to compensate for that behavior and claims Spiteful Wall preserves brace for actual incoming pressure.

This creates an unnecessary cancel/re-add path and obscures the intended mechanic.

**Correction:** stop discarding Brace merely for being engaged, and remove the compensating shared bonus. Spiteful Wall's actual incoming-pressure behavior remains in the pressure handler.

### Finding J — some direct heals bypass continuous verb scaling

The shared continuous-progression contract scales `MutationMeddley_TryHeal`, but a few concrete paths still call `ParentObject.Heal(...)` directly.

Known cases:

- Carapace + Regeneration stationary heal
- Brineborn Draw Brine automatic recovery
- Walking Colony Knit Flesh automatic recovery

**Correction:** route mutation-owned healing through the shared scaled heal helper unless the mechanic explicitly intends unscaled raw HP restoration.

### Finding K — action UI and resource UI can lie if they own separate formulas

This follows from B but is important enough to be a release gate.

**Correction:** a resource's current/max display, action cost, and reaction readiness are generated by the same mutation that actually modifies that resource.

### Finding L — branch action names should change naturally without duplicate buttons

A rank-1 action can become a different branch action at rank 3. Recreating the action blindly can leave stale entries if saved IDs drift.

**Correction:** sync against the persisted action GUID and branch signature. If the signature changes, remove the old ability and add exactly one replacement.

### Finding M — Carapace dormancy must remove only mutation-specific actions

Carapace Evolution may persist while vanilla Carapace is absent.

**Correction:** the primary Carapace action and Retune disappear while dormant; the evolution state remains intact. Biology continues to show the mutation as dormant and explain why.

### Finding N — player support installation needs independent fallback paths

The support must survive new-game creation order, older saves, and mutations arriving after character creation.

**Correction:** use all of the following, idempotently:

1. documented `PlayerMutator` new-game install
2. documented `CallAfterGameLoaded` save-load install
3. every MM adaptive mutation ensures the support on player mutation registration/mutation lifecycle
4. every MM adaptive mutation ensures it again on EndTurn if somehow absent
5. Biology itself self-refreshes on open

`RequirePart` keeps the operation duplicate-safe.

### Finding O — reaction percentages must remain truthful

The current roster's core reactions are deterministic conditional reactions, not random procs.

**Correction:** show `100%` when the documented trigger would fire with current required state, `0%` when the required state is definitely absent, and make the qualifying event explicit when no target/event exists yet. Do not invent random chance.

### Finding P — outgoing “damage dispatched” is not the same as observed HP loss

The bonus-damage result deliberately exposes multiple semantics: dispatch, event continuation, and observed HP loss. Some concrete consumers treat dispatch as proof that a retaliation actually hurt the target.

**Correction for this sweep:** audit every use. Resource refund/branch messages that require actual inflicted damage should prefer observed HP loss; mechanics that only care that the retaliatory event was emitted may use dispatch. Do not globally substitute one field without checking the mechanic.

### Finding Q — double damage-event uncertainty remains a research gate

Several mutations listen to both `TookDamage` and `TookEnvironmentalDamage`. It is not yet proven from the installed target whether one environmental incident can invoke both paths.

**Correction:** retain current behavior until exact runtime tracing proves duplication. Add this to the mandatory DEV regression matrix rather than introducing a guessed dedupe that could suppress two legitimate attacks in one turn.

### Finding R — contact classification still has an adjacent-ranged edge case

The conservative close-contact gate uses adjacency plus melee engagement. An adjacent ranged hit while engaged could still resemble contact.

**Correction:** keep the conservative gate until an exact attack-type/event field is verified in the target build. Add a regression test and DEV trace requirement.

### Finding S — environment classification remains heuristic

Wet/saline/hot/smoky currently use a mixture of Qud's exposed cell/liquid calls and string heuristics.

**Correction:** do not replace working heuristics with guessed APIs. Centralize future environment work under the existing 0.8 environment subsystem plan. For `0.7.1`, telemetry must call the mutation's real predicates so UI and mechanics at least agree.

### Finding T — nonserialized applied-stat cache needs load testing

The delta-commit fix uses a nonserialized cache while Qud's `StatShifter` itself is persisted with the mutation/part state.

**Correction:** preserve the safer no-zero/reapply algorithm, but add save/reload tests specifically checking that an unchanged stat does not remain stale or duplicate after load. Do not guess at unverified `StatShifter` internals.

## Target architecture

### Concrete mutation

Owns:

- resource state
- resource cap
- generation/decay
- branch behavior
- primary activated ability name
- primary activated ability description
- primary action execution
- reaction telemetry
- resource telemetry
- action/reaction messages

### Adaptive mutation base

Owns only shared mechanics:

- stance ability lifecycle
- primary-action ability lifecycle
- generic command dispatch
- action transaction/energy handling
- shared continuous progression
- shared stat-shift accumulation/commit
- shared Biology support installation hook
- generic Biology read-only wrappers

### Biology support

Owns:

- one universal inspector ability
- owned-MM-mutation discovery
- controller option lists
- aggregate current-modifier view
- aggregate reaction view
- aggregate ecology view
- routing a Biology-selected action into the mutation's own action transaction

Does **not** own:

- mutation state parsing
- resource keys
- cap formulas
- mutation-specific action effects
- mutation-specific reaction formulas

## Primary ability lifecycle contract

For every adaptive mutation:

1. derive a stable command from the mutation class
2. read the saved primary-action GUID/signature from existing evolution metadata
3. decide whether an action should exist
4. if dormant/unavailable, remove the saved action if present and clear only action metadata
5. if GUID points to no live ability, create a replacement
6. if branch signature changed, remove old ability and add the new branch action
7. if identity did not change, keep the same GUID and only refresh the description
8. never create two action abilities for one mutation
9. successful action spends 1000 energy
10. failed/cancelled action spends no resource and no energy

## Stance ability lifecycle contract

Retune exists only if:

- the mutation is functionally active, and
- at least one stance choice currently exists.

At rank 1/2, no Retune button.

When an identity is chosen at rank 3, Retune appears.

If Carapace Evolution goes dormant, Retune disappears without deleting the selected mode/evolution metadata.

Selecting the current stance remains free.

## Biology lifecycle contract

`Mutation Meddley Biology` is player-global rather than mutation-specific.

Installation is idempotent and redundant by design:

- new-game mutator
- after-load hook
- mutation-side ensure
- turn-side ensure

The inspector remains available even if installed before the mutation list is populated. Opening it always performs a fresh scan.

## Save-compatibility contract

Do not remove or reorder established public serialized fields.

Preserve:

- `MutationMeddley_EvolutionState`
- `MutationMeddley_EvolveAbilityID`
- `MutationMeddley_ModeAbilityID`
- current Biology support public GUID/signature fields, even when deprecated

Primary-action persistence is added as metadata keys inside `MutationMeddley_EvolutionState`, not as new public fields.

## Concrete mutation action contract

### Carapace Evolution

Baseline: `Brace Shell`

- wounded + Brace > 0: spend 1 Brace and heal using scaled mutation healing
- otherwise if Brace below cap: deliberately gain 1 Brace
- healthy + full Brace: fail free

Fortress: `Fortify Shell`

- wounded + Brace > 0: spend 1 Brace for scaled recovery

Hunter: `Drive Shell`

- wounded + Impact > 0: spend 1 Impact for scaled recovery

Adaptive: `Discharge Attunement`

- wounded + any attunement: spend one point from the highest current attunement for scaled recovery

### Living Crystal

- wounded + Stress > 0: spend 1 Stress for scaled recovery

Prismatic: `Refract Lattice`

- wounded + Dawn/Dusk > 0: spend one point from the stronger alignment for scaled recovery

Resonant: `Resonant Release`

- wounded + Release > 0: spend 1 Release for scaled recovery
- otherwise if Release is empty and raw Cadence >= 2: convert 2 raw Cadence into 1 Release

### Brineborn

Baseline: `Draw Brine`

- wounded + Reserve > 0: spend 1 Reserve for scaled recovery

Wellspring: `Draw Brine`

- convert 1 Reserve into up to 2 Mend

Saltglass: `Raise Saltglass`

- convert 1 Reserve into 1 Bastion

- convert 1 Reserve into 1 Wake

### Ash Metabolism

Baseline: `Cauterize`

- wounded + Ember > 0: spend 1 Ember for scaled recovery

Furnace: `Bank Kiln`

- convert 1 Ember into 1 Kiln

Cinder: `Stoke Rush`

- convert 1 Ember into 1 Rush

- convert 1 Ember into 1 Haze

### Walking Colony

Baseline: `Redistribute Pressure`

- wounded + Pressure >= 2: spend 2 Pressure for scaled recovery

Surveyor: `Map Pursuit`

## Resource telemetry contract

The following current/max values come directly from concrete mutation code:

- Carapace: Brace, Impact, Heat, Mire, Rime
- Living Crystal: Stress, Dawn, Dusk, Cadence/effective Cadence, Release
- Brineborn: Reserve, Mend, Bastion, Wake
- Ash Metabolism: Embers, Kiln, Rush, Haze
- Walking Colony: Pressure, Stitch, Scout, stride, Delegated Load

No Biology-side duplicate cap functions are permitted after the refactor.

## Reaction telemetry contract

For every branch, display:

- reaction name
- trigger
- current deterministic readiness/chance
- resource cost
- effect

If the reaction requires a future event whose target/source is not yet known, phrase the state as:

`Current chance: 100% on the next qualifying adjacent melee contact.`

If a required meter is empty:

`Current chance: 0% — no Scout available.`

## Direct-heal normalization

All mutation-owned healing goes through `MutationMeddley_TryHeal(...)` unless explicitly documented as raw healing.

This ensures rank-4/7/10 verb growth applies consistently.

## Spiteful Wall normalization

Spiteful Wall no longer burns Brace simply because the character ended a turn engaged.

- normal stationary Fortress generation remains
- actual incoming pressure can spend Brace
- the shared compensating fake +1 Brace path is removed

## Support-file consolidation

Replace the nine partial Biology files with:

- `MutationMeddley_BiologySupport.cs`
- `MutationMeddley_BiologySupport.Install.cs`

Keep the existing class name and legacy public fields for save compatibility.

## Performance sweep

### Remove

- repeated Biology parsing of the serialized evolution string
- duplicated cap calculations
- duplicated mutation action switches
- repeated action removal/recreation when only a resource amount changed

### Keep for now

- small player-only Biology description refreshes
- existing string state envelope for save compatibility
- existing event architecture until verified minimal-event replacements exist

### Future candidate

A nonserialized parsed-state cache may reduce allocations further, but it should be added only with a dedicated save/reload test because the state envelope is central to save compatibility.

## Release gate

This sweep is not considered runtime-complete until the exact commit passes the installed Qud compiler and the following are observed in-game:

1. new game: Biology appears
2. new game: rank-1 MM mutation action appears
3. new game: useless Retune does not appear before rank 3
4. rank-3 evolution: action transforms and Retune appears
5. Biology shows the same live resource values as mutation detail text
6. direct and Biology-routed actions perform identically
7. no duplicate action abilities after save/reload
8. Tighten Carapace produces no MM-driven HP/max-HP churn
9. deterministic reactions report truthful 0%/100% readiness
10. no Mutation Meddley runtime exceptions
11. no contact-meter recursion regression
12. multi-hour normal play remains comprehensible without reading source

## Deferred research gates

The following are intentionally not guessed in this sweep:

- exact minimal-event replacements for obsolete `Register` paths
- a first-class HUD resource widget API
- canonical liquid/gas/temperature semantic APIs beyond already-verified calls
- exact attack-type metadata to distinguish adjacent ranged hits from contact
- whether environmental damage fires both registered damage event names in the supported build

These are tested/researched separately and only replaced when the target build exposes a verified API.

## Permanent architecture rule after this sweep

A new mutation feature is incomplete until all five layers agree:

1. **state** — the mutation owns the resource and cap
2. **mechanic** — the mutation owns generation, spend, and reactions
3. **ability** — the mutation owns deliberate commands
4. **telemetry** — the mutation reports its own current state and reactions
5. **inspector** — Biology only aggregates those reports

There must never again be a separate player-support implementation that guesses what a concrete mutation is doing.
